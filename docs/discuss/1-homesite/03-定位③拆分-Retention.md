# 定位③ 拆分 · Retention（→ 留资率·订阅率 + 回访率）

> 父定位（来自 `00-战略定位-AARRR五棒.md`，口径甲：官网级留存 = 留资/订阅/回访）：
> **让有兴趣但还没决定的访问者，愿意留个联系方式或订阅更新、下次还能回来看进展，而不必一关页面就和我们彻底失联。**

**拆分规则**：每个叶子仍是一句 G-a 价值主张，粒度收到 **一个（用 AI 的）研发≈1 个工作日能交付**；「建什么（≈1 天）」是粒度证据。

Retention 天然分两簇：**A 留下可触达的线**（留资/订阅）与 **B 给理由回访**（让人愿意再回来）。

---

## 簇 A · 留下可持续触达的线

### ③-A1 低摩擦留资
> 让有意向的访问者，用最少的字段（一个邮箱/微信）就留下联系方式，而不必填一长串表单。
- 谁/新体验/旧成本：有意向但没决定的人 / 1–2 个字段就留下 / 旧站长表单劝退
- 建什么（≈1 天）：极简留资表单组件（1–2 字段 + 提交 + 落库/通知）

### ③-A2 留资有对价
> 让访问者清楚「留了能换到什么」（试用额度/资料/案例），而不必白填一个表单。
- 谁/新体验/旧成本：将信将疑要留资的人 / 留资即换到明确好处 / 旧站留资无对价、白填
- 建什么（≈1 天）：留资点对价文案 + 兑现物自动投递（发资料/解锁额度）

### ③-A3 订阅更新
> 让还没决定的访问者，能一键订阅产品/内容更新，而不必靠自己记得回来看。
- 谁/新体验/旧成本：暂不决定但想跟进的人 / 一键订阅被动收到更新 / 旧站只能靠自己记得回访
- 建什么（≈1 天）：订阅入口（邮箱/公众号引导）+ 订阅状态落库

---

## 簇 B · 给理由回访

### ③-B1 进展可见（changelog / 路线图）
> 让回访的访问者，能看到「上次来之后又更新了什么」，而不必觉得这站一成不变、来了也白来。
- 谁/新体验/旧成本：再次到访的人 / 看到持续进展值得追 / 旧站静止、回访无新意
- 建什么（≈1 天）：更新日志 / 路线图页（数据驱动列表）

### ③-B2 回访识别与续接
> 让再次回来的访问者，被认出来并能续上上次的进度（如上次试到哪），而不必从零开始。
- 谁/新体验/旧成本：回流的访问者 / 续上上次状态 / 旧站每次都从零、像没来过
- 建什么（≈1 天）：轻量回访识别（localStorage/cookie）+ 续接上次状态
- ⚠ 依赖：若要跨设备识别需账号体系——v0 先只做同设备（localStorage），跨设备归定位④注册后

---

## 粒度自检

- 5 个叶子，每个 ≈1 个 AI-研发工作日。
- ③-B2 v0 限定同设备识别即可控制在 1 天内；跨设备依赖账号，不在本棒。
