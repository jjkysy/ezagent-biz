# V· 官网价值链大表

> **这份文档干嘛用**：一张大表 = 一棵树。从左到右就是价值链的层级 `战略定位 → 北极星/指标 → 痛点 → 角色 → spec 卡`。PM 提需求时顺着树往右走，到 spec 卡那列拿卡号，重细节（用户故事 / 只做 / 不做 / 验收 G-g / 认领）回叶子文档 `01–05` / `W` 查。
> 
> **怎么读树**：父列**重复即留空**——同一战略定位挂多个指标，第 2 行起战略定位留空；同一指标挂多个痛点，指标留空；同一痛点挂多张卡，痛点留空。留空 = "同上"，缩进感自然浮现。
> 
> **两段**：
> - **0→1 段（树顶 4 条）**——官网现在是 0（只有本地 loom），先把它从无到有立起来。指标是**里程碑 ✓/✗**，不是率：这阶段没流量，谈"转化率/留存率"无负载、无意义。
> - **AARRR 段（① ②③④⑤）**——官网存在之后的漏斗优化，承接 0→1。指标是**率**。
> 
> **卡的归属规则**：让"东西存在"的基础设施卡（部署骨架 / demo 容器 / OG 底座 / 结果卡 / 内容管线）上移到 0→1 段；"调漏斗率"的内容卡与功能卡留在 AARRR 段。**一张卡只有一个家**，避免树里重复。卡型：功能=需开发、内容=只调内容。loom 底座（对话框/重构/发布助手）引用不自建。

## 附 · 裂变引擎两个新机制的思路（先落这里，待评审 / demo 验证）

> 来源：2026-06-25 brainstorm（七宗罪裂变机制）。两个机制都先用 demo 验证手感，再决定是否进 spec / 接 loom 底座。

### 裂变-2 路线图押注（"赌球式"预测市场）— 用户提的思路

> **demo 设计稿**：详见 `裂变-2-路线图押注-demo设计.md`（**world.cup 两层模型**：第一层"我要用/候补"采真需求，第二层"看多/看空"赌球裂变；押注不污染需求信号），产出独立 demo `demo/03-demo-路线图押注.html`。原"4 盘口对赌"思路因"押注测不出真需求"已转向，详见设计文档。
>
> 用户原话："投票页加一个赌球/赌博形式的机制，让这个页面本身也有传播性。"

**核心升级**：把"投票（弱信号、一次性）"升级成"押注 / 预测市场（强信号、有持续回访动机）"。

- **怎么玩**：每个路线图条目（想做 / 在做）可"押注"——押它在某时间窗内被做出来。下注用 **虚拟声望 / 积分（不碰真钱）**。
- **结算真相源**：**PR 合并 = 结算**（接 `W-1 GitHub 内容同步`）。这是本站独有优势——结算绑真实研发产物，天然防作弊、不可操纵；把"猜我们做什么"变成"盯 / 催我们做什么"。
- **七宗罪杠杆**：贪婪（赢战绩 / 积分）× 傲慢（战绩榜 = 眼光准的身份）× 嫉妒（看别人押中眼红）。
- **裂变引擎**：约同行对赌（"赌不赌这个先上线？"）= 点对点强传播；战绩榜 + 待结算仓位 = 持续回访（喂 ③）。
- **双轨防污染**：**投票 = 需求强度**，**押注 = 时间预测**，两维度分开记，避免押注扭曲真实需求信号。
- **合规红线（用户要求"合法"）**：必须虚拟积分 / 声望，**不涉真金、不可提现、无赔率兑付**——是"预测游戏 / 战绩"，不是赌博。对外用"押注预测 / 战绩榜 / 眼光排行"，避开"赌真钱"措辞。
- **结算透明**：每笔结算可点开看对应 PR / Milestone，绑真相源展示。

### 裂变-1 指挥官驾照（攀比晒卡测试）— 本轮先做此 demo

- **入口**：独立页 / 弹层，~5 题（你管几个渠道？同时跑几个任务？是否手动盯每一步？任务类型？AI 用法成熟度？）。
- **产物**：一张身份卡 = 段位（青铜单线程 → 白银双线 → … → 王者并发指挥官）+ 百分位（"超过 92%"）+ 唯一编号（#000137）+ 一句吐槽 / 夸。
- **七宗罪**：傲慢（晒段位）+ 嫉妒（看别人段位更高 → 不服再测）。两头驱动 = 自带复制循环。
- **技术价值植入**：题目本身科普"并发 agent 编排"；高段位描述里点出"这正是 ezagent 让你做到的"。
- **需求信号（副产②）**：答题选项 → persona（赵 / 钱 / 孙）+ 成熟度；结果页埋软 CTA → ③留资 / 投票。
- **可行性 🟢**：纯静态题库 + canvas 出卡即可；编号可先 localStorage 自增 mock。
- **现状**：独立原型 `demo/02-demo-指挥官驾照.html` 已跑通（intro → 5 题 → 驾照卡）。

#### 裂变-1 待迭代方向（2026-06-25 demo 评审后提出，待讨论方案再动手）

**方向① · 融入官网**：测试不做成孤立页，要嵌进 `demo/官网原型-全站-暗黑玻璃.html`。

- 待定：形态（站内新 `data-page-panel` 还是 overlay）+ 复用站点 nav / i18n / liquid-glass / reveal，不重复造 token。
- 待定：结果卡接入 ③留资 / ②投票 / ⑤分享（复用 ①-A2 OG）；**分享链应直达带结果参数的落地页**（朋友先看到"分享者的段位"→ 激发"我也测"的嫉妒闭环），而非首页。

**方向② · 部分题目游戏化（试玩，非纯选择题）**：选择题"可以随便选"、信号弱、无沉浸感。把"能力类"题改成小游戏——让访客**真的试着同时指挥几个 agent**，用行为数据（而非自报）算段位；游戏本身**顺带就是产品试用**（并这条与原 #5「并发吞吐竞技场」合流）。

- 可行性升级到 🟡（小游戏需 game loop / 状态，仍可纯 vanilla 单文件做）。

**已定方案（2026-06-25 讨论后，直接做进 `demo/官网原型-全站-暗黑玻璃.html`）**：测试 = 伪装成攀比测试的**需求雷达**，五步流——
1. intro（嫉妒钩子）→ 2. 行业一选〔直接收行业，给游戏染色〕→ 3. **并发调度小游戏**〔行为测段位 + 哪类任务最常「静默卡住」= 间接收痛点；游戏顺带演示「消息没人接住就丢」的核心命题〕→ 4. 痛点一问〔直接收痛点，选项由行业 + 游戏漏得最多的预填〕→ 5. 驾照卡（段位 + 百分位 + 编号 + 行业标签 + "你想甩掉：X"）。
- 形态：站内新 `data-page-panel="license"` + 首页 hero 钩子入口；**分享链带结果参数 URL**（落地先显示分享者段位 → 嫉妒闭环）。
- 闭环：结果卡软 CTA「把这条痛点顶上路线图 →」直接 `setPage('roadmap')`，把 ⑤ 攀比流量灌进 ② 真实需求。
- 双重痛点信号：嘴上说的（④ 自报）+ 手上露的（③ 游戏行为）互相印证。

**游戏改版（2026-06-25 二次讨论 · v1 打地鼠版作废）**：旧"并发调度"只考反应速度、不考编排，意义不明确 → 重设计为「Agent 指挥台」。
- **架构**：一个引擎 + **领域内容包**（决策题/任务/皮肤换皮，引擎不变；形/内容分离）；百分位**领域内**比较（"超过 83% 的跨境卖家"，更可信更愿转）。
- **考验三层**（叠加）：① 自调并发 + 领域决策打断（地基）② 验证关（抓 agent 幻觉/错误输出）③ 依赖编排（DAG，看懂哪些能并行）。不做"委派质量"（难量化）。
- **核心循环**：DAG 任务板，只有"可派"能开 agent；开几个你说了算（slot 上限）；agent 跑到一半阻塞弹决策卡/验证卡（带倒计时，不答=卡死失误，答错=产出有毛病）。能稳定维持的"正确并发上限"=段位；开得多但答错→段位反而低。
- **映射 ezagent**：权限决策=CapBAC、验货抓幻觉=DLQ/KB 过时、依赖派活=编排运行时；结尾点题"一个人扛不住 N 个 agent 的把关，ezagent 替你做"。
- **v1 内容包**：程序员（Claude Code/terminal 皮）+ 跨境电商（ERP/dashboard 皮）；其余领域走通用 fallback。
- **建造顺序**：地基层（DAG+自调并发+决策卡）先跑通程序员包 → 验手感 → 叠验证关 → 扩 ecom 包。
