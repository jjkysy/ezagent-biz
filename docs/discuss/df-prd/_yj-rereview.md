## 一、原评审三个致命伤：逐个判定

### 致命伤 ①：用户情境混淆（"自己用"和"卖别人"混成一个用户）—— 判定：**解掉 ✓**

原病灶：材料按情境 A（dogfood 自用）写，却把情境 B（卖别的团队）的动作（PMF 测分 / PLG 自助 / 差异化叙事 / 北极星）全塞进来，两个用户价值天差地别却不分层核算。

收口后实际改动（已核查落点）：
- **定位单一化**：00 §一句话定位、02 §〇、04 §〇、06 第五部分四处口径一致——唯一用户情境 = ezagent 团队自己用它开发 ezagent 面向不同用户群体的真实产品。情境 B 明确标"后续阶段"，当前**不写、不核算**。
- **对外动作系统性降级**：02 周历周六 PMF 行直接标"对外动作、当前不做"；周二访谈、周日复盘、下注会等标"可选/后置"；竞品分析节（02 §四、06 §二）每条都补了"先内部跑通、比体验是后续阶段的事"。
- **旧体验/净值重判**：02 §〇明确"旧体验=飞书+GitHub+群+脑子，旧体验较低，净值为正"——这正是 framework 要的"找到旧体验≈0 的完美新用户"，而且找到的是真实存在的那一个（自己），不是虚构的。

判定 **解掉 ✓**。这是收口动作最干净的一关：混淆的根源是脚踏两只船，船拆了，混淆自然消失。残留只是 06 §1.0/S6 速查 SOP 仍有旧 PMF 字样（已就近标注修正口径，revision-log §四自承待统一），属文字债不是逻辑债。

### 致命伤 ②：agent 赌注无价值验证（9.5 周排期里没一个阶段正面验"对齐时长真降了"）—— 判定：**解掉 ✓（设计层面）**

原病灶：整个差异化系于"每人一个 agent 降对齐成本而非制造噪音"，材料自标"最高不确定性"却把它排进核心路径、不前置验证；验收全是"能追踪+能对话"的功能可用性，没有一条是价值兑现。

收口后实际改动：
- **05 阶段 1 立了价值闸门**（~2 周）：3-5 人、挑一个真实在做的最小 ezagent 功能、实测每周对齐耗时（会议+刷群分钟）+ 返工事件 + agent 主动消息有用率。**白纸黑字写"降了再往阶段 2 走；没降或全员把 agent 静音就停"**——把核心风险从 10 周压到 2 周。
- **功能/价值验收双轨拆开**：05 阶段 1 明确区分"e2e 功能验收（做没做出来）"和"价值验收（价值有没有兑现，硬门槛）"。04 功能 3 闭环判据从"能追踪+能对话"改成"对齐时长实测下降 X%"，并点破"ICE Confidence 7 只评技术能搭，不等于价值能兑现"。
- **06 机制 3 点破"诚实标注 ≠ 已处理风险"**，把验证前置写死。

判定 **解掉 ✓**，但限定"设计层面"——闸门只是被设计出来、还没真跑。这恰恰是俞军最看重的"落到可实践验证"：方案现在指向一个 2 周能做能验的动作，且给了明确止损线。剩下的是执行风险（见第三节真问题 1），不是设计缺陷。

### 致命伤 ③：是不是一门生意（无定价、无商业模式、无 ROI 实算，"有利润"空白）—— 判定：**部分解（作为内部工具：解掉 ✓ / 作为生意：刻意挂起）**

原病灶："有利润"属性整份空白，ROI 反复当口号从没真算，连"这是内部工具还是要卖钱的产品"都没回答。

收口后实际改动：
- **第 0 问已答**：它就是 ezagent 的第一个产品，当前阶段回收是间接的——省下 ezagent 自身产品开发的返工/对齐/脱节成本。
- **06 第二点五真给了回本公式**：投入=10 周人天折钱 + **机会成本（这 10 周 2 人不做主线的什么，明确标"必算项不能略"）**；回收=返工下降数 + 对齐省时 + 废功能减少数，三个 × **全部钉为阶段 1 实测值**，并写"三个 × 实测都 ≤0 则回本周期=∞、项目本身不成立"。这是 framework 要的"有利润可间接但必须说清回收逻辑"——回收逻辑现在清楚了。
- **机会成本论证补上**：02 §〇之二 + 06 §二点五两层论证（它本身就是产品 / 它顺带验证三套主线能力），且诚实标"技术验证收益别和省时收益混算重复计数"。

为什么只判"部分解"而非全解：**作为"一门对外生意"，这一问被刻意挂起了，不是答了**。06 §二点五第 3 条明说"对外商业回报暂时不写、不假装写得出"。这是诚实且正确的收口（不在没外部验证时编商业模式），但要如实记账：**这套材料现在论证的是"一个值得自研的内部工具"，没有论证"一门生意"**。对内部工具这个判定对象，③ 算解掉 ✓；对"它最终是不是生意"，③ 是被正确地推迟到外部验证之后，当前无法判、也不该判。

## 二、用户价值公式：对 ezagent 团队这个真实用户，净值现在是正是负

把"ezagent 团队自己"当作真实用户，套 **用户价值 = 新体验 − 旧体验 − 替换成本**：

- **新体验**：节点必被认领+未认领显式"待分配"（对齐/漏接↓）、产物挂回节点成唯一索引（查找时间↓）、一页看全队状态无会对齐（对齐时长↓）、每人一个 agent 替你盯（对齐↓，**但价值未验证**）。
- **旧体验**：飞书+GitHub+群+脑子——**确实较低**（一团乱、靠刷群、产物散落）。这是收口后最关键的变量翻转：对外卖给 Linear/Notion 成熟团队时旧体验极高、净值为负；对内自己用旧体验低，分子立刻变大。
- **替换成本**：**迁移成本≈0**（团队无历史工具沉淀要搬，04 各价值卡反复点到这是替换成本低的关键）；学习成本中（认领=Grant/挂载=slice 新心智）；运维成本中（自己跑 BEAM/SPA build/双向同步，但自己人自担可接受）；信任成本集中在 agent 答不准。

**净值判定：对 ezagent 团队这个真实用户，当前为正（功能 1/2/4/5 净值明显为正，过 2.5× 线；功能 3 agent 净值待阶段 1 实测）。** 关键支撑：旧体验低 + 迁移成本≈0 这两条把对外为负的核算直接翻成对内为正。这不是话术翻转，是"换了真实用户"后公式分子分母同时朝有利方向变——正是俞军"找旧体验≈0 的完美新用户"该有的样子。

**唯一的负值风险集中在 agent（功能 3）**：它是唯一真新体验，但价值未兑现、信任成本可能吃掉价值。所以整体净值能否坐实为正，押在阶段 1 那 2 周实测上——这也正是闸门要守的东西。

## 三、还剩哪些真问题（诚实，不放水）

1. **闸门只设计了、还没跑；且"红了怎么办"只给了"停"，没给替代路径。** revision-log §四自承。"停"是负责任的止损，但一个团队投了几周脚手架后真要它停、不给转向方案，执行时极易变成"再调调 agent 提示词继续投"——闸门会软。**建议**：阶段 1 价值验收前就预定义"红灯后的 B 计划"（如砍掉 agent 主动盯、只留被动问答；或彻底退回纯节点+挂载不要 agent），让"停"不等于"全盘废"。

2. **核心赌注（agent）的实测设计本身有信度风险。** 3-5 人、2 周、自己测自己、样本极小且非盲，"对齐时长下降"的分钟数靠人工记录、易受霍桑效应和动机污染（团队想让它成功）。这不是不该做，而是**别把这次实测的结果当强证据**——降了也只是"没被证伪"，不是"已证实"。06 机制 3 已要求"agent 有用率/答准率"交叉看，建议再加一条"对齐时长用客观痕迹（会议日历时长/群消息计数）而非自报"以降污染。

3. **"内部 ROI 跑正"与"机会成本"两本账可能打架，且都未填数。** 06 §二点五诚实把机会成本列为必算项,但"这 10 周 2 人不做主线"的代价没法在阶段 1 内被量化（主线少推进的价值是反事实，测不出）。结果是:回收侧能实测、成本侧的机会成本只能"团队拍板"。**这意味着 ROI 账最终仍有一半是主观判断**——这是诚实的现状，但要警惕它退回"口号"：建议把机会成本至少写成一个具体的"放弃了哪个主线功能"的清单,而不是抽象的"主线价值"。

4. **三位一体（开发/产品/运营兄弟节点强制配齐）是新增的强约束,自身未被验证。** 整改把"三位一体覆盖率"提为北极星之一,但"强制每个开发节点配产品+运营兄弟节点"会显著抬高系统2 负担(每开一个开发节点要开三个),可能与"仪式最小集收口"的减负方向内部张力。它和 agent 赌注一样属于"听起来对、未经实测"的设计,**建议同样纳入阶段 1 观察**:三位一体覆盖率上去了,返工真的下降吗?还是只是多填了两个占位节点。

5. **R1（页面树能否渲染导图/看板）仍是悬顶剑,且影响面最大。** 05 已把它提到阶段 0/1 最先实测(好),但失败则"柱子1整条换传输面"——这是返工面最大的 unverified 点,比 agent 赌注的工程风险更硬。闸门关注了价值赌注,别让 R1 这个技术赌注在阶段 0 被轻轻带过。

## 四、合格判定（作为内部工具）

### 【有条件合格】

收口动作真实解掉了原评审两关(情境混淆、agent 无价值验证),第三关(是不是生意)对"内部工具"这个判定对象已答、对"生意"被正确挂起。五维复审:用户价值核算对真实用户(自己)净值为正(从原 2/5 升至约 3.5/5)、好产品三属性中"有利润"有了可实测的间接回收逻辑(从空白升至约 3/5)、决策质量因前置闸门+预期效用乘法补上而走强(约 4/5)。**触发原"维度一 1-2 分直接不合格"的硬规则已不再命中**;但"可持续(商业层)"仍因对外生意挂起而无法判定,按规则"最高有条件合格"。补救条件=第三节五条真问题中的 1/2/3(预定义红灯 B 计划、实测用客观痕迹防污染、机会成本落成具体放弃清单)。

**一句话结论**:收口为内部工具后,这套材料从"对外不合格"变成"对内有条件合格"——它现在论证的是一个对真实用户(ezagent 团队自己)净值为正、且把最不确定的 agent 赌注前置到 2 周可证伪闸门的内部工具,底层交易逻辑成立、止损线清晰,只待阶段 1 实测把净值和 ROI 从"设计上为正"坐实成"实测为正"。

**最关键的 3 条仍需注意**:
1. **闸门要真守、红灯要预设 B 计划**:阶段 1 "没降就停"不能软成"再调调继续投";红灯前就定义好"砍 agent 主动盯/退回纯节点"的转向路径,让止损可执行。
2. **核心赌注实测要防污染**:3-5 人 2 周自测样本小、易受霍桑效应,对齐时长用日历/群消息客观痕迹而非自报,且降了只算"未被证伪"不算"已证实"。
3. **三位一体与机会成本两块新债**:三位一体强约束自身未验证(可能抬高系统2 负担却不降返工,纳入阶段 1 观察);机会成本必须落成"放弃了哪个具体主线功能"的清单,别让 ROI 账退回口号。
