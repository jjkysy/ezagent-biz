## 〇、评审对象类型

**主类型 = A（内部 spec / PRD），强叠 C（商业策略 / 增长方案）的必查项，并含一处 B（招商）味道。**

判别依据：
- 这套文档"想让读者做什么"？主要是**让团队照着开发**（04 是 MVP spec、05 是 9.5 周技术排期、06 是可执行 SOP）——这是 A。
- 但它不止 spec：03/02/06 在卖一套"会转的发动机"打法（战略→开发→运营→ROI 闭环），要决策层认这个方向值得投 9.5 周 + 持续运营投入——这是 C，必须**狠追机会成本 + 短期 vs 长期生态 + 可持续**。
- 00 的差异化主张（"别人是任务工具+AI 插件，我们是思维导图+每人一个 agent+产物自动挂载"）+ "差异化赌注"措辞，带 B 类**卡位性断言**味道，按 B 必查项**主动核验真实竞品**（下面会做）。

**因此本评审按 A 类（无配重偏移）打底，叠加 C 类"机会成本 / 可持续"必查项，并对 03/00 的差异化主张套 B 类"竞品核验 + 藏起来的致命假设"。** 这是混合体，已在开头注明。

## 一、方案翻译（交易本质还原）

按 evaluate 要求，先把这套材料翻译成俞军语言。**翻译得出来的部分质量不错；翻译不出来的部分恰恰是最大的洞。**

### 谁是用户？

材料自己写了：**3–10 人早期产品团队（产研运设混编、无专职对齐、追求高频迭代、能接受 agent 进工作流），首批=我们自己**（03 §3.1）。

**但这里藏着这套材料最致命的一个混淆——"用户"和"自己"是同一拨人。** 这不是普通的 dogfooding，是"产品的唯一已知用户就是开发它的团队"。按俞军"用户=特定情境下的需求集合"，真正要审的两个不同情境被混成了一个：
- **情境 A（dogfood 内用）**：我们一边开发 ezagent 主线、一边用这个 workspace 管自己。旧体验=飞书+GitHub+群+脑子。
- **情境 B（对外卖给别的团队）**：别的 3–10 人团队拿这个 workspace 管他们的产品开发。旧体验=Linear / Notion / 飞书项目，**且他们已经在用、有重度沉淀**。

材料通篇按情境 A 写（dogfooding、自己用自己），但定位（00/03 §1.3）、差异化、北极星、PMF 测分、PLG 自助路径、对外叙事（07.x）全是情境 B 的动作。**两个情境的用户价值天差地别，材料没分层核算，这是第一隐患**（完全对应 framework.md 范例里"大卖家 vs 小卖家混为一谈"的翻车）。

### 这是一笔什么交易？

- 卖方（这个 workspace）提供：一张能认领、能挂产物、有 agent 盯、有网页出口的"活导图 + 编排运行时"。
- 买方支付：**学习成本（一套全新的"节点状态机+认领+挂载+agent 对话"心智模型）+ 迁移成本（已经在 Linear/Notion/飞书里的项目数据和肌肉记忆）+ 时间成本（每天 spec / 每周 6 个仪式 / 周日复盘）+ 信任成本（agent 答不准会自信说错）+ 运维成本（自己跑一个 BEAM 服务节点、SPA build、飞书/GitHub 双向同步）**。

**注意：买方支付的清单里，材料只认真算了"开发成本"（9.5 周排期很细），几乎没算"用户的非货币支付"——这正是用户价值公式里最该挖的部分。**

### 旧的利益平衡是什么？

情境 B 的用户现在用 **Linear（cycle + changelog + triage goalie）+ Notion（中枢）+ 飞书项目 + ChatGPT/Claude 插件**满足同一组需求。材料在 06 自己引用了这些公司的做法当"案例支撑"——**它引用的每一个案例公司，恰恰都是它的直接竞品**。Linear 的 changelog 钟摆、Notion 的 dogfooding 中枢、Figma 的人人认领、Superhuman 的 PMF 引擎——这些不是"无人做过的方法",是"竞品已经在产品里做到了的能力"。材料把竞品的成熟实践当成"我们要缝进来的方法",却没问一句:**用户为什么要从已经做到这些的工具迁过来?**

> **翻译小结**：材料能翻译成"谁、什么情境、用什么支付、换取什么效用"——所以它**是产品方案，不是纯功能描述**，这一点过关。但它把两个用户情境混成一个、把用户的非货币支付几乎略去、把竞品当案例引却不当竞品防——这三条决定了下面五维的扣分位置。

## 二、五维评审

> 每维：评分（1-5）+ 关键发现 + 改进建议。已带入 A 类默认配重 + C 类"机会成本/可持续"加重 + B 类"竞品核验"。

### 维度一：用户价值核算 [2/5] — 红线维度，是整份材料最弱的一环

套 **用户价值 = 新体验 − 旧体验 − 替换成本**：

**新体验**（靠什么新要素）：材料的新要素是"思维导图当骨架 + 每人一个长期 agent 当神经 + 产物自动挂回当血肉"。其中：
- "思维导图骨架"——**不是新要素**。Linear 有 Roadmap→Projects→Cycles 的树，Notion 有数据库视图，机会-方案树本身是公开方法。用户感知层面这接近**旧要素的重新组合**。
- "产物自动挂回节点"——有一点真新体验，但 06 自己承认 GitHub/飞书双向同步是要自研的两大块、且 R7（飞书变更订阅）unverified，**这个新体验当前是承诺式的，不是已交付的**（B 类"承诺 vs 现实缺口"必查项命中）。
- "每人一个长期 agent"——**这是唯一可能的真新要素**，但 06 机制 3 自己诚实标注"**没有现成公司做过完全一样的事、案例支撑最弱、最高不确定性**"，且最大失效风险是 agent 噪音 + 答不准。也就是说：**唯一的真新体验，恰恰是最没把握能兑现成正效用的那个**。

**旧体验**：材料几乎没有正面核算旧体验有多好。情境 B 用户的旧体验是 **Linear/Notion 这种打磨多年、体验极好的成熟工具**——旧体验**远不是 ≈0**。材料没有找到"旧体验≈0 的完美新用户"切入点（按 framework，这是最大化净值的合法途径），反而一头扎进旧体验最高的红海。情境 A（自己用）倒是旧体验较低（自己原来就是飞书+群一团乱），但情境 A 的"用户"只有一个团队、且没有付费交易，**撑不起一个产品**。

**替换成本**（最易低估，往死里挖）：材料**严重低估**。一个团队要从 Linear/Notion 迁过来，付出的是：
- 认知成本：全新的"节点状态机 / 认领=Grant / 挂载=slice / agent 平等参会"心智，**远高于** Linear 那种"系统1 就能上手"的交互。
- 迁移成本：已有项目/文档/历史全在旧工具里，材料只字未提"怎么迁",默认按"从零团队"讲（B 类典型翻车点：回避"已在用对手产品的用户怎么迁"）。
- 运维成本：要自己跑 BEAM 服务节点、SPA build、双向同步——**这是 Linear/Notion 用户根本不需要承担的成本**。
- 信任成本：agent 答不准"比没有 agent 更坏"（材料自己说的）。

**净值判定**：套损失厌恶 2.5× 红线——用户换回的价值要 > 支付代价的 2.5 倍交易才成立。**对情境 B（对外卖）用户，净值大概率为负**：新体验弱（多数是旧要素重组+承诺式功能），旧体验高（Linear/Notion 体验极好），替换成本极高（认知+迁移+运维+信任）。这正是 framework 里"子弹短信 vs 微信"的结构——**真新体验（agent）抵不过极高替换成本，用户不迁移**。对情境 A（自己用）净值可能为正，但那不是一个产品，是一个内部工具。

> 维度一 2 分，按 evaluate 总判定规则"维度一 1-2 分→直接不合格"。这不是说这个东西没价值，而是说**作为对外产品的用户价值核算不成立**；作为内部 dogfooding 工具另说（见最终判定）。

**改进建议**：
1. **明确锁定情境 A（先做纯内部工具），暂时砍掉所有情境 B 的对外动作**（PMF 测分、PLG 自助路径、对外叙事、差异化 vs Linear）。一个产品先把"对一个真实用户（自己）旧体验≈0、净值明显正"做实，再谈外卖。
2. 若坚持要做对外产品，**必须找到旧体验≈0 的完美新用户**——不是"在用 Linear 的成熟团队"，而是"刚组队、还没工具沉淀、且强 AI-native"的新团队，对他们替换成本才低。把 ICP 从"3-10 人早期团队"收窄到"旧体验≈0 的那一类"。
3. **把"用户的非货币支付"写进 spec**：每个功能旁边除了 ICE，补一栏"它给用户增加了多少学习/迁移/运维/信任成本"。现在 spec 只算开发成本，不算用户支付成本——这是核算失真的根。

### 维度二：好产品三属性 [2/5] — "可持续"和"有利润"基本是空白

- **有效用**：对情境 A 成立（自己用着确实能串起来），对情境 B 存疑（见维度一）。**勉强算半个有效用。**
- **有利润**：**材料里几乎找不到回收逻辑**。通篇没有定价、没有商业模式、没有"这东西怎么变现 / 战略价值怎么回收"。06 第三部分把"复杂结算"列为"MVP 不做"，但**连最基本的"这是个内部工具还是要卖钱的产品 / 卖给谁 / 怎么收费"都没回答**。按 framework，"有利润可间接但必须说清回收逻辑"——这里连间接逻辑都没有。如果定位是纯内部 dogfooding 工具，那"利润"=节省自己的开发成本，**但材料没有算这笔账：自研 9.5 周 + 持续维护，省下来的对齐时间够不够回本？** 这笔 ROI 账材料自己反复提"ROI 闭环"却从没真算过。
- **可持续**（C 类加重，最该深挖）：材料对"机制可持续"做了不错的体检（06 第二部分五个机制的失效分析很诚实），**但对"产品/商业可持续"零分**——因为根本没有商业模式，无从谈"用户利益与商业利益长期统一"。更要命的是 06 第四部分自己列出的三种失败模式（过度仪式化 / 工具碎片 / agent 噪音）**都是结构性的、且解药都依赖人为纪律**（"盯结果指标""砍仪式""抽样核对准确率"）——这些靠纪律维持的平衡，正是 framework 警告的"可持续无法靠推演证明、只能靠实践验证"。材料给了哨兵指标（这点是加分项），但没给"如果哨兵报警、纪律维持不住，这套体系会不会自我崩溃"的答案。

> 三属性中"有利润"和"可持续（商业层）"都是 1-2 分。按规则"可持续 1-2 分→最高只能有条件合格"。但这里更根本的问题是**整套材料回避了"这到底是不是一门生意"这个第 0 问题**。

**改进建议**：
1. **先回答一个二选一并写进 00**：这是（a）纯内部 dogfooding 工具（那就别写差异化/PMF/对外叙事，把 02/06 的对外运营全砍掉，ROI 只算"省自己的时间"），还是（b）要对外卖的产品（那就必须补定价、补 ICP 收窄、补迁移路径）。**现在它脚踏两只船，两边都没做实。**
2. 若选（a），**真算一次内部 ROI**：自研 9.5 周（按团队人天折钱）+ 每月维护成本 vs 每周省下的对齐时长×团队时薪×52 周。算出来回本周期，这才是"有利润"的间接逻辑。
3. 若选（b），补一页最简单的商业假设：卖给谁、按什么收费、第一个愿意付费的非自己团队从哪来。

### 维度三：用户模型审查 [3/5] — 异质性和情境性有硬伤，但 dogfooding 假设的可塑性是亮点

用五属性拷问：
- **异质性 [翻车]**：把"3-10 人早期团队"当单一画像，但 3 人团队和 10 人团队对"6 个每周仪式 + 轮值 goalie + 下注会"的承受力天差地别。06 自己也承认"团队太小（3 人）撑不起这么多角色轮值"——**这说明画像内部就是异质的，材料知道却没在 spec 里拆**。
- **情境性 [翻车]**：核心病。前面说的"情境 A（自己用）vs 情境 B（卖别人）"混淆，就是情境性没锚定。需求强度在两个情境里完全不同。
- **可塑性 [亮点]**：dogfooding"自己用自己、用着难受当场变新节点"是对可塑性的正向利用——用真实使用塑造产品，这点做得对，case 支撑也强（Notion/Figma）。
- **自利性 [基本过关]**：没有明显指望用户损己利他。各岗位认领自己那层、agent 替自己盯，激励是相容的。
- **有限理性 [翻车]**：这是和 framework "好设计顺应系统1"冲突最大的一条。整套体系要求用户**持续启动系统2**——每天写 spec、过质量门、填挂钩牌、看四个哨兵指标、跑 6 个每周仪式、每 4-6 周重塑机会树。这是**极高认知负担**的设计。framework 明确："要求启动系统2的设计转化率天然低。"材料自己在失败模式 1（过度仪式化）里预见了这个风险，但缓解办法（"砍仪式"）是事后补救，不是设计上就顺应系统1。

> 3 分：可塑性的正向利用 + 自利性相容把分数托住，但异质性/情境性/有限理性三条翻车把它压在及格线。

**改进建议**：
1. **把"3-10 人"拆成至少两档画像**（如"3-4 人精简循环"vs"7-10 人完整循环"），分别给不同的仪式密度，写进 spec。
2. **把仪式数砍到系统1 能承受的量**：MVP 第一圈只留"日 spec + 周 changelog"两个（06 第三部分其实已经这么建议了，但 02/03 的周历又摆了 7 个仪式——文档内部打架，要统一收口到最小集）。

### 维度四：交易模型与利益相关方 [3/5] — 技术侧利益相关方分析扎实，但商业侧多边模型缺失

把每个相关方当用户核算：
- **团队成员（使用者）**：分析较充分（四角色旅程 04 第二部分写得细），利害得失基本正向。**这是材料最强的部分。**
- **agent（作为参与者）**：作为利益相关方核算了噪音/答不准风险，诚实。
- **ezagent 主产线（被 dogfood 的对象）**：这是个隐藏的关键相关方——**这个 workspace 的开发会不会抢 ezagent 主线的研发资源？** 9.5 周自研 + 持续维护，机会成本是"这 9.5 周不做 ezagent 主线功能"。材料完全没算这笔机会成本（C 类必查项"机会成本"——framework 原话"策略评审不追机会成本=没评"）。
- **付费方/市场**：**完全缺失**，因为没有商业模式。多边平衡无从谈起。

**企业视角/ROI**：材料反复说"ROI 闭环""北极星""输入指标",但**这些都是产品内部运营指标，不是企业获利机会的核算**。真正的企业视角问题——"做这个 workspace 是不是一个真实的市场获利机会？资源投这里、不投 ezagent 主线/不投别的，边际收益还为正吗？"——材料没回答。

> 3 分：使用者侧 + 技术相关方分析扎实（加分），但机会成本未算 + 商业侧多边模型缺失（C 类硬伤），压在及格线。

**改进建议**：
1. **补一段机会成本核算**：明确写"做这个 workspace 的 9.5 周，放弃的是 ezagent 主线的什么？为什么 dogfooding 工具的边际收益 > 直接做主线功能？" 这是 C 类不能省的一刀。
2. 如果定位是内部工具，把"利益相关方"收敛到"团队 + ezagent 主产线"两方，把对外的"市场/付费方"明确划掉，别留半张脸。

### 维度五：决策质量审查 [3/5] — 证伪意识和诚实度是全套材料的最大优点，但有一个致命假设没被正面验证

这一维材料表现明显好于其他维度，**值得表扬的地方先说**：
- **证伪设计到位**：05 风险表 R1-R10 标了 unverified、06 第二部分五机制做了"可能在哪失效"、第四部分列了三种失败模式 + 可观测信号。这是 framework 说的"成熟方案会主动指出哪层推理错了整个就垮"——**做到了，这是真本事，是全套材料里最俞军的部分。**
- **权衡取舍明说**：MVP 边界（先不做 world/agent-schema/动态UI/PMF引擎）、必要 vs 后置分得清楚，没有"全都要"。
- **诚实标注不确定性**：个人 agent"案例支撑最弱、差异化赌注"——主动暴露自己最虚的地方，这是 framework 极其看重的品质。

**但用 decision 八视角扫描，挖出三个深层问题**：

1. **参照系被悄悄换了（最致命）**。08-06 把 Linear/Notion/Figma/Superhuman/Stripe/Basecamp 当"案例支撑"——但**这些是竞品，不是案例**。材料用了一个偷换参照系的手法：把"竞品已经做到的能力"重新叙述成"我们要缝进来的成熟方法",于是竞品从"我要打败的对手"变成了"给我背书的前辈"。一查就清楚：Linear 的 cycle+changelog+triage、Notion 的 dogfooding 中枢、Figma 的人人认领——**这些都是竞品产品里已经规模化交付的能力**。材料的差异化主张"别人是任务工具+AI插件,我们是思维导图+agent"在这个参照系下站不住:Linear 早有 AI、Notion 早有 AI、它们的体验还远好于一个要自己跑 BEAM 的自研工具。**B 类竞品核验命中:差异化主张在真实竞品面前被大幅削弱。**

2. **最致命假设没被正面验证**。整套材料的成败系于一个假设：**"每人一个长期 agent 能真正降低对齐成本（对齐时长下降），而不是制造噪音"**。材料把它列为"差异化赌注 + 最高不确定性 + 案例支撑最弱"，**但验证计划是什么？** 05 阶段 1 只验"能追踪+能对话"（功能可用性），**没有验"对齐时长真的降了"（价值兑现）**。R9 验的是"agent 能否被触发式调用"（技术可行），也不是价值。**也就是说：最该先证伪的那个价值假设，整个 9.5 周排期里没有一个阶段正面验它。** 这正是 framework 范例的致命病——"最关键的假设恰恰没验证"。

3. **预期效用 =（收益 − 成本）× 概率 没算**。材料只算了"如果成功"的收益（对齐时长降、闭环数升），没乘以成功概率（agent 赌注自己说"最高不确定性"=概率低），也没认真算成本（9.5 周 + 机会成本 + 用户替换成本）。按 decision，预期效用 =（收益−成本）×概率——一个"高收益 × 低概率 − 高成本"的赌注，期望值可能是负的。材料没做这个乘法。

> 3 分：证伪意识 + 诚实度 + 权衡明说是真优点（本可给 4），但参照系被换 + 最致命假设没安排验证 + 预期效用没算，把它压回 3。

**改进建议**：
1. **把"对齐时长下降"做成阶段 1 的硬验收**，而不是阶段 1 之后的运营指标。在最小 curl flavor 上，找 3-5 个人用两周，**实测对齐时长降没降**——降了再往下做，没降就停，别造完整套再发现核心赌注不成立。这是把 9.5 周的风险压到 2 周。
2. **把"案例"改写成"竞品分析"**：06 第二部分每个机制旁边，老实写"这个能力 Linear/Notion 已经做到什么程度，我们凭什么做得更好/不同"。把背书参照系换回竞争参照系。
3. **补一行预期效用估算**：个人 agent 赌注的（收益 × 成功概率 − 成本），哪怕是定性的"高/中/低"，逼自己面对这个乘法。

## 三、最终判定

### 【不合格】（作为"对外产品方案"）/ 【有条件合格】（作为"内部 dogfooding 工具 + 技术验证计划"）

**判定要分两层说，因为材料自己脚踏两只船：**

- **如果这套材料是要论证"一个值得对外做的产品"** → **不合格**。触发 evaluate 硬规则两条：①维度一（用户价值）2 分→直接不合格；②"可持续（商业层）"1-2 分。核心结论：**对外卖给成熟团队这笔交易，用户价值净值大概率为负**——新体验多是旧要素重组+承诺式功能，旧体验是体验极好的 Linear/Notion，替换成本（认知+迁移+运维+信任）极高，且 2.5× 损失厌恶红线下根本过不去。它把竞品当案例引、把两个用户情境混成一个、最致命的 agent 赌注没安排价值验证、连"是不是一门生意"都没回答。

- **如果这套材料是"我们自己用的内部工具 + 一次 ezagent 能力的 dogfooding 技术验证"** → **有条件合格**。因为：情境 A 下旧体验较低、净值可能为正；技术落地分析扎实（四柱一地基、现成/要写/在建分得清、风险表诚实）；证伪意识和诚实度是真优点。**补救条件**见下面整改清单第 1-4 条（核心是：明确收口成内部工具、砍掉对外动作、先用 2 周验"对齐时长下降"这个核心赌注、真算一次内部 ROI）。

**一句话核心结论**：这套设计能不能让"有效用、有利润、可持续"的交易更多发生？——**作为内部工具，能让"有效用"的内部协作更多发生（前提是核心 agent 赌注先验证）；作为对外产品，"有利润"和"可持续"两个属性是空的、用户价值核算不成立，不能。**

**最致命的 3 个问题（按严重程度）**：
1. **用户价值核算不成立 + 用户情境混淆**：把"自己用"和"卖别人"混成一个用户，对外情境净值为负，对内情境又不是产品。
2. **最致命的 agent 赌注没有价值验证计划**：9.5 周排期里没有一个阶段正面验"对齐时长真的降了",最该先证伪的恰恰没验。
3. **回避了"这是不是一门生意"的第 0 问题**：无定价、无商业模式、无内部 ROI 实算，"有利润"属性空白。

**达到合格线优先改**：先做整改清单第 1（二选一收口）、第 2（前置验证核心赌注）、第 3（真算 ROI）三条——这三条做完，"有条件合格（内部工具）"就能坐实。

## 四、最致命的认知漏洞 / 未验证假设 / 只报喜的套话

### 致命认知漏洞
1. **把竞品当案例（参照系偷换）**：06 引用的 6 家公司全是直接竞品，材料把它们的成熟能力叙述成"给自己背书的方法",掩盖了"用户为什么要从已做到这些的工具迁过来"这个要命问题。
2. **把 dogfooding 的便利当成产品的价值**："自己用着顺"≠"别人愿意迁过来付出替换成本"。情境 A 的低旧体验骗过了对情境 B 高替换成本的核算。
3. **把"功能可用"当成"价值兑现"**：验收标准大量是"能认领/能挂载/能对话/返 200"，几乎没有一条是"对齐时长真降了/找东西真快了"。framework A 类必查项命中——"验收只验做没做出来，不验有没有价值"。

### 最危险的未验证假设
1. **"每人一个 agent 降对齐成本而非制造噪音"**——整个差异化系于此，材料自标"最高不确定性",却没在排期里安排价值验证。
2. **"对外有团队愿意迁移"**——零外部用户验证，连一个非自己团队的访谈都没有，却已排了 PMF 引擎和 PLG 路径。
3. **"R1/R4/R7/R8/R9 这些 unverified 技术点不会推翻架构"**——材料诚实标了 unverified（好），但把它们排在阶段 1-3 里验，意味着如果 R1（页面树撑不起导图）或 R9（agent 不能主动盯）失败，前面的排期要返工。

### 只报喜的套话（点破）
- **"这套设计不是新发明，是把七套验证过的方法缝在一起"**——这句话两面性：一方面是诚实（不吹原创），另一方面是**用"成熟方法"给一个净值存疑的产品镀金**。方法成熟 ≠ 缝在一起后用户价值净值为正。子弹短信的每个功能也都"成熟"。
- **"个人 agent 是差异化赌注但案例支撑最弱"**——这句诚实标注本身是优点，但它被用作了"免责声明"：标注了不确定，却没改变把它排进核心路径、不前置验证的决策。**诚实标注不等于已经处理了风险。**
- **"北极星=周用户价值闭环数"**——听起来很俞军，但"闭环数"在 dogfooding 内用场景下是**活动指标伪装成结果指标**：自己给自己数闭环，没有外部用户用上、付费、留存来检验,这个"价值闭环"可能是自说自话。真结果指标应该是"对齐时长降了多少""有没有第一个非自己团队愿意用"。

## 六、一句话收口

这套材料**技术落地分析扎实、证伪意识和诚实度突出**（风险表/失效分析/必要性分层是真本事，比绝大多数 PRD 强），**但产品层有三个穿不过去的硬伤**：用户情境混淆导致用户价值核算对外为负、最致命的 agent 赌注没有价值验证、回避了"是不是一门生意"。**判定：作为对外产品不合格，作为内部工具+技术验证有条件合格。** 先做整改清单前 3 条（收口定位、前置验 agent 赌注、真算 ROI），把它坐实成一个"对一个真实用户（自己）净值明显为正、且核心赌注已被 2 周实测验证"的内部工具——这是它当前唯一站得住的形态。
